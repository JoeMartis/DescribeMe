# Landing the redesign on `redesign`

Drop-in replacements for the branch, built from the code on
`JoeMartis/DescribeMe@redesign`. No build step, no dependencies — same static
three files.

> **Historical.** This describes landing the two-pane workspace redesign
> itself. The visual system it references (Caprasimo/Figtree, "Organic") has
> since been replaced twice over — first by Living Isle (`krofft` branch),
> then by the current Modernist system (`minimal_design` branch) — see the
> note at the top of `style.css` for the current fonts.

## What changed, functionally

- **First-run screen** — key, retention and model, gated on
  `describeme.onboarded` in `localStorage`. After that, settings live in a
  native `<dialog>` opened from the header.
- **Two-pane workspace** — slide rail left, selected slide + its description
  right. `selectedJobId` drives the detail pane; `renderJobState()` now updates
  one rail row plus the detail pane instead of a whole card.
- **Approve is the export gate.** `job.approved` decides what the .zip
  contains. `A` approves and jumps to the next unapproved slide; `←`/`→` move
  between slides (ignored while focus is in a field or the dialog is open).
- **Per-slide revisions** — "More detail", "Shorter", "Redo with <stronger
  model>" re-run one slide with an extra system addendum. The previous
  description is pushed onto `job.history`, so "Undo revision" restores it. A
  revision clears `approved` — it needs looking at again.
- **Inline editing** — the preview goes `contenteditable`; on save the markup
  goes back through `sanitizeHtmlFragment()` before it becomes `resultHtml`.
  `contenteditable` is now stripped by the sanitizer so it can't leak into an
  export.
- **Zip export** — a store-only ZIP writer (CRC-32 + local headers + central
  directory, ~70 lines, no dependency since the CSP forbids a CDN). Contains
  one HTML fragment per approved slide, plus an `index.html` with all of
  them — plain semantic HTML with no accompanying CSS, so it drops in
  anywhere without fighting a host page's stylesheet.
- **Batch name** — defaults to the common prefix of the filenames, editable in
  the header; names the exported zip.
- **Cost** — header chip shows the estimate for the whole batch
  (per-slide estimate × queued slides). Still an estimate, never a bill.
- **Drop anywhere** — the drop target is the whole workspace, not just the
  empty state.

## Kept as-is

Everything under the hood: the system prompt, verbosity levels and their
addenda, cost estimation, client-side downscaling, bounded concurrency of 3,
retry/backoff with `retry-after`, the non-JSON and CORS diagnostics, the
sanitizer (including your `TEMPLATE`/`SVG` additions), plain-text extraction,
and the settings-persistence gating you added on this branch.

Accessibility is carried over and extended: real `<input type="file">` with an
accessible name, `role="status"` / `role="alert"` live regions, per-description
`role="region"` labelled by filename, `<fieldset>`/`<legend>`, native
`<details>` and `<dialog>`, visible focus rings, and rail rows as real buttons
with `aria-current`.

## Not done — the one big thing

Nothing survives a reload. Once people are reviewing and approving 25 slides,
an accidental refresh costs money and patience. Persisting descriptions,
approvals and edits (not the images) to IndexedDB is the largest remaining
piece of work and the one your accessibility-office users will feel most.
